审查、修回与汇报

论文自审、审稿意见回复、修订核查、组会汇报与外部同行评审。

更新于 2026-09-24
Academic-Paper-SkillsResearch-Presentation-Skill

检查当前版本的主要问题

自审时，给 Agent 一份明确版本的稿件，并说明当前阶段、目标读者和希望重点检查的问题。研究尚在推进时，可以先检查论证与证据；准备投稿时，再加入格式、匿名和材料完整性的检查。

可以使用 paper-review，要求每条意见指出原文位置、判断依据和建议处理方式。模拟审稿人的意见可以帮助发现问题，但不能预测真实评审结果。

安排修改顺序

优先处理影响结论和理解的问题，例如实验与主张不对应、比较条件不一致、方法缺少关键定义。然后再处理结构、表达和排版。单纯增加文字未必能解决证据不足的问题。

记录项建议内容
位置与问题具体章节、段落、图表或实验，以及发现了什么
依据与影响为什么需要处理，会影响哪项判断
处理方式修改表述、补充说明、检查数据、补做实验，或解释保留原因
状态待讨论、处理中、已修改待核查、已核查

对 AI 提出的意见可以逐条判断。证据不足的意见先查证；不适用的建议记录原因，不必全部接受。需要大幅改写或重做图表时，分别调用写作和图表 Skill。

整理审稿意见与回复草稿

收到真实审稿意见后，保留原文和编号，将一条意见中的多个问题分别记录。每个问题对应计划采取的行动、需要修改的位置和可用证据，方便核对是否遗漏。

回复可以先写清楚回答，再说明实际修改了什么、改在哪里，以及修改后的证据。尚未完成的实验或修改保留为计划，不写成已经完成。不同意某项建议时，解释理由和现有证据，并考虑是否需要改进原文以减少误解。

核查回复与修订稿是否一致

提交前，将每条回复与修订稿、图表和实验记录逐一对应。尤其检查“新增”“修正”“重新运行”等表述，确认这些工作确实完成，文中数字、图号和页码也与最终稿一致。

审稿意见处理完，不等于投稿材料已经齐备。还需要按当次官方要求核对主稿、补充材料、回复信和系统中的字段。AI 完成检查或论文同步到 Overleaf，都不代表已经在投稿系统提交。

投稿完成后，根据系统实际状态记录稿件版本、投稿日期与后续事项。

用研究材料准备汇报

准备汇报前，说明听众、时间和本次希望讨论的问题。组会可能重点讨论新结果与下一步，论文讲解更需要交代方法和证据；不必让每种汇报都使用同一套页数和结构。

Research-Presentation-Skill 可以从项目材料或单篇论文整理汇报。使用前先明确研究问题、核心判断和可用材料，再安排各页内容。

建议让每一页承担一个明确任务：说明问题、解释方法、展示结果或提出讨论事项。把难以在有限时间内展开的技术细节放到附录。图表和数字关联到原始来源；引用其他论文的结果时，标清来源与实际含义。

汇报前用实际显示方式检查文字与图表，并按预计时长讲一遍。演讲备注中可以记录需要补充解释的条件，以及尚未解决的问题。

区分自审与外部同行评审

外部同行评审涉及他人的未公开稿件，先核对邀请方关于保密和 AI 工具的规定，以及自己获得的授权范围。确认允许后，再决定哪些材料能交给哪一种工具；没有确认前，不把稿件上传给外部服务。

More-Than-Peer-Review-Skill 用于整理有原文依据的评审草稿。使用时区分作者可见意见与编辑意见，人工核对事实、建议和结论，再按评审流程提交。

这与对自己的论文进行模拟审查是两种不同任务。选择 Skill 时说明稿件来源和任务性质，避免将修稿指令用于外部评审材料。

保留交付版本与后续事项

修回或汇报结束后，保存实际交付的版本，包括源文件、PDF 或幻灯片、相关图表，以及回复或讨论记录。把收到的新问题转成具体后续事项，记录负责人、需要的材料和下一步。

与合作者共享时，使用对方能够访问的位置。临时文件路径、个人电脑目录或受限服务器位置，可以保留在执行记录中，但不能作为对方唯一的材料入口。

项目暂时结束时，补充当前结论、未解决问题、复现入口和后续联系信息，便于之后继续。项目组织方式见 调整工作流程。
