ChatGPT 与 Skill

Chat、Work 与 Codex 模式的区别、科研使用场景，以及 Skill 的安装与调用。

更新于 2026-09-04
ChatGPTClaudeResearch-Workflow-Skills

选择 Chat、Work 或 Codex

在 ChatGPT 中，可以根据任务选择 Chat、Work 或 Codex。先看自己希望怎样推进工作，以及需要查看哪些执行细节。

模式选择

Chat、Work 与 Codex

Chat

讨论与即时问答

查看对话、引用和补充说明
Work

完成多步骤任务

查看进展、材料和交付结果
Codex

处理项目与代码

查看命令、文件差异和审查

Work 和 Codex 的能力有重叠。Work 也可以运行代码和处理仓库；Codex 也可以检索资料、写文档和制作幻灯片。选择时可以考虑自己是否需要频繁检查代码差异、命令输出和其他技术细节。OpenAI：三种工作方式

在桌面应用中，选择 ChatGPT 后可以使用 Chat，并通过模式切换启用 Work；需要开发视图时，在产品选择器中选择 Codex。

Chat：讨论与即时问答

Chat 适合需要来回讨论的任务，例如理解一个方法、分析假设是否合理、比较两种实验设置，或修改一小段文字。可以提供论文、笔记或具体段落，让 ChatGPT 根据材料解释；需要当前信息时，可以要求联网查找并给出来源。

例如：“请根据这篇论文的方法部分，解释它为什么使用这个对照组，并指出与我的设置有哪些差别。”先把疑问讨论清楚，再决定是否开展更完整的整理或分析。OpenAI：使用 Chat

Work：完成多步骤任务

Work 适合已经知道要得到什么、但完成它需要多个步骤的任务。把材料范围、输出格式和检查要求说明清楚后，ChatGPT 可以查阅资料、分析文件、调用可用工具，制作报告、表格或幻灯片。过程中可以查看进展、补充信息和调整方向。

例如：“请根据这五篇论文制作文献比较表，列出研究问题、数据、对照和主要结果；每项结论标注论文与页码，无法确认的项目留空。”完成后，应打开表格并检查引用、比较条件和遗漏项。

也可以让 Work 根据实验摘要和已有图表制作组会幻灯片，或整理一份需要反复更新的项目报告。开始前说明成品应包含哪些内容、哪些材料可以使用，以及哪些操作需要先由你确认。OpenAI：开始使用 Work

Codex：查看代码与执行细节

在 ChatGPT 桌面应用的产品选择器中选择 Codex，可以使用面向开发工作的视图。它会呈现 Git、命令执行、文件差异和代码审查等细节，适合需要逐项检查实现过程的任务。OpenAI：桌面端 Work 与 Codex 的区别

在科研中，可以用它排查数据处理脚本、修复测试、修改论文源文件，或检查一次 Git 同步将影响哪些文件。给出项目目录、复现方式和预期行为，有助于把操作限制在相关范围。

开始 Codex 任务前

先选择已有项目目录，或为新项目确定一个稳定目录，再开始修改文件。新建任务、工作区或对话不会自动形成项目管理方式；需要保留的代码、结果和记录应回到项目目录与 Git 历史中。具体做法见 项目与上下文管理。

例如：“请在这个项目中复现绘图脚本的报错，修复后用现有数据运行，保存图和修改说明。保留原始数据，并列出实际执行的检查。”结束时查看文件差异与运行结果，再判断修改是否符合要求。

区分本地与云端任务

任务在哪里运行，会影响它能访问哪些文件和工具。

运行位置材料与工具如何提供什么时候使用
本地通过桌面应用使用已授权的本机文件、应用和浏览器需要操作本地研究目录、论文仓库或已有软件环境时
云端使用上传的文件、支持的项目资料和已授权连接；不能直接读取本机目录或浏览器会话材料已提供给云端，希望任务在关机后继续，或从其他设备继续处理时

桌面端 Work 可以在功能可用时选择 Work locally 或 Cloud。Codex 的 Local 和 Worktree 都在本机运行；Worktree 使用独立的 Git 工作树隔离文件改动，Cloud 则使用配置好的云端环境。Work 本地与云端说明、Codex 运行环境

例如，上传论文 PDF 可以让任务阅读论文；要修改 LaTeX 并通过 Git 同步，还需要提供源文件仓库及相应环境。模式、工具和本地访问是否可用，取决于账号、平台及工作区设置；开始前确认当前任务实际能访问的材料。文件与设备访问范围

如果主要使用 Claude Code，可以参考 claude-scholar。安装方式按该项目说明处理，不需要同时安装两套承担相同任务的工具。

区分 Skill、插件和工具连接

名称用途如何判断是否需要
Skill保存一类任务的步骤与配套资料需要 Agent 重复执行同类任务时
插件打包并分发 Skill 与连接器项目通过插件提供安装入口时
MCP 或工具连接让 Agent 访问或操作外部服务需要访问 TaskBoard 等系统时

Skill 通常以 SKILL.md 为入口。它说明如何处理任务，但不会自动提供外部系统的账号或权限。比如安装了项目管理 Skill，仍需单独配置 TaskBoard 连接。OpenAI Skill 说明

在 ChatGPT 中安装 Skill

安装本地 Skill 时，可以在 ChatGPT 桌面应用的 Codex 模式中，把仓库链接和要安装的 Skill 一起交给 Agent。说明操作系统、安装范围和当前环境，并明确要求完成安装。

例如，Research-Workflow-Skills 的仓库根目录包含两个独立的 Skill 目录。下面的指令只安装工作区治理这一项。需要实验管理时，再安装 experiment-design-management。项目安装说明

AI 操作指令

安装工作区治理 Skill

查看完整指令
请在我的 ChatGPT 桌面应用的 Codex 模式中安装 research-workspace-governance。
来源：https://github.com/DELONG-L/Research-Workflow-Skills
仓库分支：main
Skill 目录：research-workspace-governance

先读取当前安装说明，并检查是否已有同名安装。
没有安装时，使用适合当前本地环境的安装方式完成安装；已有安装时，先报告来源和本地修改，不要覆盖。
完成后检查 Skill 结构与依赖，告诉我实际安装位置、可用名称，以及是否需要刷新或重启客户端。
本次不初始化或修改任何研究项目。
将【占位信息】替换为实际内容后，再发送给 Agent。

对于其他仓库，可以使用下面的通用指令。某些项目提供插件，另一些提供独立 Skill；由 Agent 读取当前说明，选择适合你所用客户端的安装方式。

从公开项目安装 Skill

请在【客户端及模式，例如 ChatGPT 桌面应用的 Codex 模式】中安装下面的 Skill：
项目链接：【公开 GitHub 仓库链接】
要安装的功能或 Skill：【名称】
使用范围：【个人多个项目使用／仅当前项目使用】

先读取项目当前说明，确认应该安装独立 Skill 还是插件，以及真正包含 SKILL.md 的目录。
检查已有安装；有同名目录或本地修改时，先说明情况，不要覆盖。
按当前客户端支持的方式安装所选内容，不批量安装无关功能。
完成后报告来源、安装位置、依赖检查结果和调用方式。需要账号授权的部分，请说明我应在哪里完成。
将【占位信息】替换为实际内容后，再发送给 Agent。

本地安装可以使用 skill-installer 从其他仓库取得 Skill。独立 Skill 支持桌面应用及相应本地开发入口；需要在 Chat、Work 的其他端使用时，应确认它是否通过插件提供。安装后检查当前任务能否发现它；未出现时按客户端提示刷新或重启。安装与发现机制

检查是否可以使用

安装完成后，先核对来源、实际安装位置、Skill 名称和所需依赖。再让 Agent 在一个小任务中明确使用它，检查是否读取了对应说明。

建议第一次先处理已有的公开材料或一个范围明确的本地任务。例如，让工作区治理 Skill 只检查目录并提出建议；让 Knows 检索一个一般性主题。安装成功与完成一次任务是两个不同的检查结果。

AI 操作指令

检查 Skill 是否可用

查看完整指令
请检查当前会话能否使用【Skill 名称】。
如果可用，请读取它的说明，概括适用任务和所需工具。
然后用它检查【一个指定的项目目录或公开材料】，只给出检查结果和建议。
本次不移动文件、不提交远程写入、不运行长实验。
请区分：Skill 已被发现、说明已读取、所需工具可用，以及这次实际完成的检查。
将【占位信息】替换为实际内容后，再发送给 Agent。

如果 Agent 找不到 Skill，检查安装目录是否属于当前客户端、是否安装到了另一台机器，以及当前会话是否已发现新安装。若 Skill 能加载但某项工具不可用，应继续查相应依赖或连接，不必重复安装全部内容。

说明任务范围与预期结果

使用时，写清要处理的对象、希望得到的结果和本次允许的操作。Skill 名称可以帮助 Agent 选择流程，但实际任务仍需要你说明。

例如：“请使用 research-workspace-governance 检查这个项目的目录和仓库关系，给出调整建议，本次先不移动文件。”这比只发送 Skill 名称更容易确定工作范围。

grilling 适合通过提问补充条件；planning-with-files 适合需要跨会话推进的任务。一次简短问答通常不需要为它建立完整计划。具体用法见 项目与上下文管理 和 文献与研究空白。

更新已有安装

更新前，先确认现有版本是否有本地修改。建议记录来源仓库、版本或提交，以及个人调整；更新时比较差异，保留需要继续使用的改动。

如果多套 Skill 都处理同一类任务，可以明确本次使用哪一套。不同工具给出不一致的流程时，先看项目已经约定的做法，再决定是否调整。

Q&A

常见问题

3 个问题
Q01Chat、Work 和 Codex 必须固定选择一种吗？
A

不需要。同一个研究项目可以在不同阶段使用不同模式：一般讨论用 Chat，需要持续处理材料时用 Work，需要直接检查和修改项目文件时用 Codex。

Q02安装 Skill 后，就能直接访问外部工具和组内系统吗？
A

不能。Skill 提供处理任务的说明；外部服务仍需要相应的连接方式、账号和权限。

Q03需要一次安装手册中提到的所有 Skill 吗？
A

不需要。先按当前任务安装需要的项目，确认可以使用后，再随研究任务补充。
