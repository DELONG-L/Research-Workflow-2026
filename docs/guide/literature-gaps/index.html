文献与研究空白

使用 Knows 整理相关文献与证据，通过比较和初步验证判断候选问题是否需要继续研究。

更新于 2026-09-24
KnowsgrillingZotero

确定研究问题

使用 Knows 前，先写下研究对象、要解决的问题、已有方法的限制，以及自己考虑的做法。如果目前只有一个主题，也可以先检索和阅读，不必急着给出贡献。

“研究长上下文模型”是主题；“在某种任务和资源限制下改变哪一步计算，并用什么结果判断改动有用”才便于与已有工作比较。这里的条件越明确，后续检索和讨论越容易限定范围。

AI 操作指令

用 grilling 明确候选问题

查看完整指令
请使用 grilling，帮助我明确下面的候选研究问题。
主题：【主题】
目前的问题描述：【描述】
考虑的方法：【方法，尚未确定可以写未确定】
已有材料：【论文或项目文件】

请先读材料，再逐项询问研究对象、成立条件、最接近的工作、拟改变的操作和验证方式。
每次只讨论一个关键问题；能够从材料确认的信息不必重复问我。
结束时整理已明确的内容、尚未确认的假设和下一步需要查证的材料。
将【占位信息】替换为实际内容后，再发送给 Agent。

使用 Knows 检索文献

Knows 提供检索、阅读、比较和研究方向分析等功能。安装后，可以直接用自然语言描述任务，不必先记住所有内部模块名。

面向主题的检索使用 knows.academy 的文献库。它的覆盖范围可能与其他检索来源不同；没有找到结果时，应记录覆盖不足、连接失败或其他具体原因，不据此判断没有相关研究。Knows 使用说明

AI 操作指令

检索与当前问题相关的文献

查看完整指令
请使用 Knows 检索【研究主题】。
我的具体问题是：【问题】
重点条件：【数据、场景、方法、时间范围或其他限制】

先确认当前文献库对该主题的覆盖情况。
列出最相关的一组论文，说明每篇与当前问题的关系，并给出可查阅的来源。
记录检索关键词、日期、检索来源和没有覆盖的部分。
区分没有检索到结果、文献库覆盖不足和工具调用失败。
本次整理候选阅读清单，不生成正式 BibTeX。
将【占位信息】替换为实际内容后，再发送给 Agent。

对于库中覆盖较少的方向，可以另外在出版社页面、学术搜索或领域数据库中补充检索。记录所用关键词、日期和来源，有助于之后判断结果涵盖了哪些范围。

核对论文原文与结构化记录

Knows 可以使用 .knows.yaml 文件保存论文的主张、证据、限制和出处，这类伴随论文的文件称为 sidecar。它适合给 Agent 重复读取，也便于在多篇论文之间比较。

Sidecar 可能只覆盖论文的一部分。涉及关键结论、实验数字或适用条件时，检查其来源位置；缺少证据的部分需要回到论文原文。结构校验通过只能说明记录格式符合要求，不能证明内容转述正确。Knows 的记录形式

如果处理的是你已有的本地 PDF，明确提供文件，并请 Agent 确认当前安装支持的阅读或生成流程。主题检索与本地文件处理是不同任务，不要假定把文件夹名称写进检索词就会读取其中的论文。

AI 操作指令

整理并核对一篇论文

查看完整指令
请使用 Knows 整理【明确的论文文件或链接】。
先确认当前安装支持的阅读方式；若有 sidecar，检查它对应的论文版本和覆盖范围。

整理研究问题、核心方法、关键假设、证据与限制。
对主要结论和实验数字，给出原文页码、章节、表格或其他可定位位置。
区分作者结论、你的归纳，以及当前资料无法确认的内容。
如果生成 .knows.yaml，请按当前版本校验结构，并列出仍需回到原文核对的部分。
将【占位信息】替换为实际内容后，再发送给 Agent。

正式参考文献仍按 Zotero 与参考文献 中的流程处理。Knows 生成的条目或 AI 给出的 DOI 可以作为核实线索，不直接代替人工核验与 BibTeX 导出。

比较最接近的已有工作

先找真正接近自己做法的论文，再讨论区别。引用最多或标题最相似的文章不一定是最接近的工作；应比较问题设置、方法操作和成立条件。

比较项需要记录的内容
研究问题输入、输出、目标与使用场景
假设与限制数据条件、可用信息、计算或通信限制
方法实际改变了哪一步，依赖什么信息
证据使用的数据、基线、评价指标和主要结果
与候选方案的关系相同部分、不同部分，以及还无法判断的部分

区别可以是适用条件、分析结论或新的能力，但需要说明为什么有意义。更换数据集、调整名称或组合已有模块，并不能单独说明研究贡献。

AI 操作指令

比较候选方案与最接近工作

查看完整指令
请使用 Knows 比较【候选方案描述】与【最接近的论文清单或材料】。

按研究问题、输入输出、假设、具体方法操作、实验设置和适用限制整理比较表。
每个相同点或区别附上对应的原文位置；证据不足时标为待核实。
特别检查是否只是更换名称、数据集或组合方式，实际操作仍与已有工作相同。
最后列出当前可以确认的区别、可能重复的部分，以及需要补充检索的问题。
将【占位信息】替换为实际内容后，再发送给 Agent。

记录候选研究空白

把研究空白暂时写成需要验证的判断，附上它来自哪些材料。建议区分以下几种情况：

  • 原文明确指出的未解决问题或限制。
  • 多篇工作比较后，发现某个条件或操作尚未覆盖。
  • 当前检索没有找到的内容，需要扩大范围再查。
  • 证据还不够，暂时无法判断是否存在空白。

前两类也不等于一定值得立项。仍需判断问题的重要性、可行性，以及是否有其他工作已经解决。

Knows 的新颖性检查可用于查找接近或重复的工作，但结论受其能够检索到的资料限制。PURSUE 等工具标签只作为继续调查的线索，不是新颖性或可发表性的保证。新颖性检查的范围

安排一次初步验证

对一个候选方向，先确定最可能影响后续判断的假设。它可能通过一个小实验、一个反例、一段证明或对已有代码的检查来验证。

验证前写清输入、比较对象、观察结果和判断方式。例如，什么结果支持继续调查，什么结果说明要调整方法，什么情况说明当前方案与已有工作重复。

AI 操作指令

为候选方向安排初步验证

查看完整指令
请基于【候选研究方向】和【已有文献比较记录】，安排一次初步验证。

先指出最需要验证的假设，并说明它与最接近工作有何关系。
给出尽量小的检查方式：可以是实验、反例、证明尝试或代码检查。
列出所需输入、比较对象、观察内容，以及继续、调整或停止当前方案的判断依据。
区分已知事实和待验证假设，并注明尚未覆盖的文献范围。
本次只整理探索性验证计划，不提交计算作业，也不把结果写成已经成立的结论。
将【占位信息】替换为实际内容后，再发送给 Agent。

这一阶段可以保留探索性记录。决定开展正式实验后，再使用 experiment-design-management 整理协议、分析计划和执行记录。初步程序能够运行，不等于已经证明研究假设。

保存讨论结果

建议保存检索范围、关键论文、比较表、当前候选问题、未解决的疑问和初步验证计划。内容放在当前项目中，后续会话从这些材料继续。

需要与导师讨论时，可以将问题、相关证据和需要判断的事项整理成共享记录。已经否定的方向也可以保留简短原因，避免重复同一轮检查。
